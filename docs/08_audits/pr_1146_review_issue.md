# GitHub Issue: Post-PR #1146 Master PR Review & Operational Hardening Report

## Overview & Scope
This report serves as the master post-PR review for **PR #1146** (`fix(security): stop overriding SvelteKit's hash CSP with 'unsafe-inline' in hooks`).

The purpose of PR #1146 was to eliminate a security header conflict where manual response headers in SvelteKit `handle` hooks were overriding SvelteKit's built-in, sha256 hash-based Content Security Policy (CSP) with `'unsafe-inline'` script permissions.

PR #1146 successfully established `svelte.config.js` as the single source of truth for CSP directives (`mode: 'hash'`), removing manual `Content-Security-Policy` header manipulations from `src/lib/server/request-policy.ts`'s `applySecurityHeaders()` while retaining all non-CSP security headers (`X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, `Strict-Transport-Security`, `X-Request-Id`).

This issue report documents the technical findings, risk evaluations, acceptance criteria, and actionable tasks for the next engineering session.

---

## Technical Analysis of PR #1146 Changes

### 1. `svelte.config.js` (CSP Engine Configuration)
- **Finding:** SvelteKit's CSP configuration is defined in `mode: 'hash'`.
- **Directives:**
  - `script-src: ['self', 'https://challenges.cloudflare.com']`: Protects script execution; inline scripts generated during SSR are automatically hashed by SvelteKit.
  - `form-action: ['self', 'https://accounts.google.com', 'https://checkout.stripe.com', 'https://billing.stripe.com']`: Allows 303 redirects during Google OAuth, Stripe Checkout, and Stripe Customer Portal flows without browser blocking.
  - `worker-src: ['self', 'blob:']`: Supports Sentry Replay background web worker compression.
- **Impact:** Eliminates `'unsafe-inline'` script execution across all server-rendered pages.

### 2. `src/lib/server/request-policy.ts` (`applySecurityHeaders`)
- **Finding:** Manual `Content-Security-Policy` setting was removed from `applySecurityHeaders()`.
- **Impact:** Prevents header duplication or accidental downgrade of SvelteKit's computed sha256 script hashes.

### 3. Documentation & Code Invariants
- **Finding:** Security rules in `docs/04_engineering/security_rules.md` and `docs/04_engineering/security_plan.md` were updated to reflect single-source CSP handling.
- **Requirement:** `pnpm lint:no-comments` enforces zero code comments in `src/`; architectural justifications are documented in `docs/`.
